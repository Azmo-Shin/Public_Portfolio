# 감성 모델이 사람 판정과 어긋날 때 — 원인 가설을 하나씩 지운 기록

> 관련 폴더: [09 로컬 LLM 평가 · 감성모델 진단](../09_local_llm_eval_sentiment_diag/) · [05 한국어 리뷰 감성](../05_korean_sentiment_kcelectra/)
> 정확도 실측치·리뷰 원문은 싣지 않습니다. 이 글은 **진단 순서와 판단**만 다룹니다.

## 문제: "모델이 이상한 것 같다"는 말

운영 중인 리뷰 감성 분류 모델(KcELECTRA 기반, [05](../05_korean_sentiment_kcelectra/))의 결과가 현업이 읽어 본 느낌과 다르다는 이야기가 나왔습니다. 이럴 때 가장 쉬운 대응은 "더 큰 모델로 바꾸자"입니다. 하지만 원인이 모델이 아니라 **표본**이나 **라벨 정의**에 있다면, 모델을 바꿔도 같은 불만이 다시 나옵니다. 그래서 바꾸기 전에 먼저 어디서 어긋나는지를 좁히기로 했습니다.

## 1단계: 지금 돌고 있는 모델이 무엇인지부터 확정

의외로 첫 질문은 "운영 중인 모델이 어느 것인가"였습니다. 후보 모델 폴더가 여러 개 있었기 때문입니다. 운영 분류 결과 표본을 후보 모델 다섯 개로 각각 다시 돌려 **일치율로 운영 모델을 확정**했습니다. 진단 대상이 틀리면 이후 실험은 전부 의미가 없습니다.

## 2단계: 같은 표본에서 비교

사람이 직접 판정한 표본을 만들고, 기존 모델과 LLM 후보들을 **같은 문항**에서 비교했습니다. 모델마다 다른 표본으로 잰 정확도는 비교할 수 없기 때문입니다.

## 3단계: 원인 가설을 실험으로 하나씩 지우기

정확도가 낮게 나온 이유로 생각할 수 있는 가설을 나열하고, 가설마다 그것만 바꾸는 실험을 했습니다.

| 가설 | 확인 방법 |
|---|---|
| ① 표본 편향 — 모델끼리 갈린 "어려운 리뷰"만 뽑혔다 | 무작위 표본과 나란히 비교 |
| ② 중립의 정의가 다르다 | 라벨링 가이드 기준으로 다시 채점 |
| ③ 학습 라벨에 오류가 있다 | 특정 관용구가 어느 라벨로 학습됐는지 집계 |
| ④ 카테고리 사전이 오탐한다 | 특정 어휘의 오분류 사례 추적 |

반대로 **원인이 아님을 실험으로 확인해 배제**한 것도 기록했습니다. 사전확률 보정, 토큰 잘림, 이모지 제거가 그렇습니다. 배제한 가설을 적어 두면 다음 사람이 같은 실험을 반복하지 않습니다.

## 결론을 "다음 작업"으로 연결

진단은 보고서로 끝내지 않고 후속 작업으로 이어 붙였습니다. 라벨을 정정한 뒤 재학습하고, 가이드 기준으로 LLM을 다시 시험하는 것입니다. "모델이 나쁘다"가 아니라 **"이 라벨 정의와 이 학습 라벨이 문제다"**로 바뀌면, 고칠 대상이 분명해집니다.

## 배운 점

- 모델을 바꾸기 전에 **진단 대상(운영 모델)·비교 표본·정답 정의**를 먼저 고정한다.
- 가설은 한 번에 하나만 바꿔 확인하고, **배제한 가설도 결과로 남긴다**.
- 같은 원칙을 GPU 전환에도 썼습니다. 파이프라인을 CPU·GPU로 끝까지 돌려 **결과가 한 칸이라도 다르면 전환하지 않는다**는 기준입니다([09](../09_local_llm_eval_sentiment_diag/)).
